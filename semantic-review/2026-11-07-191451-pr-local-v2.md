## High-level view
Rxfail handling is now symmetric: C++ applies the same window rule to heard and unheard watches and exports `wd_heard_rxfail` per link. Python estimates a per-observer coincidence rate `b_i` and recovers drops as `U/(1-b_i)`, capped at `A+U` per node. This removes the load-dependent upward bias of the old discard method.
The remaining weakness is the estimator's key assumption: that a failure in the window is as likely for a dropped packet as for a heard one. It fails in one direction (overestimating `b`), which pushes trust down. That direction is acceptable for a security signal, and the stage-2 gate (est_corrected vs `true_tx_ratio`) is the right place to measure it.
The `self_*` leak is now structural for trust (whitelisted `trust_view`), while the columns remain in the CSV by design.

2. **Cap hides bias at node level (possible)** — `drops_est = min(sum, A+U)` (`telemetry_trust.py`, `corrected_trust`) saturates for honest nodes with high `b`, so trust floors at about `(F+1)/(N+2)`. This is correct as a bound, but report cap-hit frequency in the eval so a saturated node is not read as an estimate.
3. **Independence is across windows only in aggregate (possible)** — `b_i` is pooled over the run, but rxfail bursts are time-correlated with load. If drops cluster in busy periods (grayhole drops are random per packet, so probably not), the pooled `b` underestimates. Check by computing `b` per window in the pilot, and use `--windows` as a sensitivity check.

### Estimator and the direction of the b bias
With `P(U | drop) = 1 - b_drop`, the expected U from drops is `D(1-b)`, so `D = U/(1-b)` is unbiased only when `b = b_drop`. A drop produces no j transmission, so its failure in window can only come from other traffic. A heard watch includes the same ambient failures plus failures correlated with j's own frames (a failed first attempt followed by a successful retry, and collisions at the observer that j's transmission provokes). Hence `b_heard >= b_drop`, D is overestimated, and trust is underestimated. For `b` around 0.4, as in the synthetic test, the inflation of U is 1/0.6 against 1/(1-b_drop), which can be large if `b_drop` is mostly ambient. This is the safe direction for a trust signal feeding routing, but it penalises honest relays in busy cells. U also includes silent misses of real forwards, which the same formula treats as drops; the `unobserved_clean_observer_miss_frac` gate in section 4 of `docs/TELEMETRY.md` is the control for that.

### Rest of the fixes
`wd_heard_rxfail` is counted only for `cat <= 1`, and the validator checks it never exceeds heard (`telemetry_schema.py:175`). Heard-after-timeout watches (`d > wdLate`) are classified A/U and excluded from the `b` denominator, which is consistent. The discard method and `self_*` whitelist behave as described, and tests mutate non-whitelisted columns.

### Not tested
Any C++ runtime behaviour, real-data `b` magnitude, and the correlation between drop times and failures.
